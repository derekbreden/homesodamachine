# Gun-positioner observation toolkit

Camera capture, optical-setting receipts, controller move receipts, append-only
session datasets, offline response fitting with held-out validation, and
bounded correction proposals for the six-axis gun positioner. The workflow,
the camera setup command sequence, the data format, and what is and is not
verified are in
[hardware/gun-positioner/observation.md](../../hardware/gun-positioner/observation.md).
Nothing here can command laser emission.

## Layout

| Path | Contents |
|---|---|
| `observe.py` | Command line: `cameras`, `clock-check`, `optics`, `validate-config`, `capture`, `format-report`, `export-frame`, `learn` (check, plan, record, jog, fit, validate, propose, execute), `simulate`, `fit`, `propose`, `check`, `schema` |
| `examples/` | Templates: `cameras.example.json`, `operator-optics.example.json`, `features.example.json`, `target.example.json`; the toolkit refuses each until every `FILL_ME` and required null is filled |
| `gpobs/` | The package; `controls.py` loads the controls host modules from `firmware/src_gun_positioner/host/`; `config.py` validates configurations and receipts; `learn.py` runs the dry-session workflow and its motion gates |
| `helper/` | `GPOCapture`, the AVFoundation capture helper. The kit ships `helper/build/GPOCapture.app`, ad-hoc signed for arm64 and ready to use on this Mac. `build.sh` rebuilds it from `main.swift` |
| `observation-schema.json` | JSON Schema of the session records, generated by `observe.py schema --write` |
| `tests/` | Unit tests with synthetic data, a simulated mechanism and a fake controls `Client` |

## Requirements

`requirements.txt`: numpy, Pillow (JPEG and PNG frames) and pyserial (VISCA
serial transport and the controls `Client`). `tools/cad-venv/bin/python`
provides numpy and Pillow; with a Python that lacks Pillow, the one test that
needs it is skipped.

The shipped `helper/build/GPOCapture.app` needs no rebuild while `main.swift` and
`Info.plist` are unchanged. `helper/build.sh` rebuilds it from source and needs
`swiftc`. An ad-hoc rebuild changes the signature, so macOS asks for camera
access again.

## Tests

```sh
tools/cad-venv/bin/python -m unittest discover -s tools/gun-positioner-observation/tests
```

The helper tests run when `helper/build/GPOCapture.app` exists
(`helper/build.sh --adhoc` builds it without using the keychain); they use the
helper's synthetic mode and open no camera.

## Controller

Moves go through the controls `Client` only via `gpobs.controls.ControlsClientBackend`,
which `gpobs.moves.MoveRecorder` refuses unless `allow_hardware=True`:

```python
from gpobs.controls import ControlsClientBackend
from gpobs.moves import MoveRecorder

backend = ControlsClientBackend.for_session("/dev/cu.usbmodemYOUR_PICO", writer)
backend.prepare(datum_established=True)          # CLEAR, REF, ARM, heartbeat
recorder = MoveRecorder(backend, writer, allow_hardware=True)
```

This path has run only against the fake `Client` in `tests/support.py`.
