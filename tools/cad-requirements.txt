# The CAD environment, pinned — what `tools/cad-venv` holds and what CI rebuilds from.
#
#     python3.13 -m venv tools/cad-venv
#     tools/cad-venv/bin/pip install -r tools/cad-requirements.txt
#
# THE PIN IS THE POINT, and `cadquery-ocp` is the pin that matters. `_cadq_export`
# canonicalizes every STEP it writes — sorted members, no mtime, no uid — which is what lets
# `pack.py` land the same bundle bytes over a tree whose geometry has not moved. That property
# holds ACROSS RUNS OF ONE OCC BUILD. A different OCC writes different curve parameterization
# for the same solid, so an unpinned kernel is a lock that churns on every build and a bundle
# that is content-addressed to nothing.
#
# Generated by `tools/cad-venv/bin/pip list --format=freeze`. Regenerate it when a package
# moves, in the commit that moves it.
#
# THE PIN ALSO DECIDES WHICH MACHINES CAN BUILD THIS AT ALL. At these versions the cp313
# wheels `cadquery-ocp` and `cadquery_vtk` publish are macosx_11_0_arm64,
# macosx_11_0_x86_64, manylinux_2_31_x86_64 and win_amd64 — and no linux aarch64. So an
# arm64 Linux runner cannot hold this environment, whatever else recommends it. Every
# other pin here resolves to a wheel on the three platforms that remain, but one: py3dbp
# is a pure-python sdist with no dependencies, and pip builds it anywhere.
