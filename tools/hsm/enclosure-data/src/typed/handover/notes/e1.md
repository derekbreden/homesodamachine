## Signatures

Part 1's 52 functions are in `$T/enclosure/p1.rs` with their final signatures (fallback bodies call
the generated function). Build pending (queued behind other runs' builds); the signatures will not
change for a compile error. Call them directly: `super::p1::interior_x(cx)?`.

## Root

`$T/enclosure.rs` (TYPED = true, set by the orchestrator). Import what you use:
`use super::{Box, Bound, BoxReadings, Cx, Pack, PortField, _ReadingBounds};`
(`Box` shadows `std::boxed::Box` where you import it; write `std::boxed::Box` for the std one).

The namedtuple structs. Each `impl Py`: `from_py` reads a Python instance in one snapshot (a
namedtuple arrives as the tuple of its fields); `to_py` calls the namespace's class (a new instance of
the same class with the same values).

- `Box { pack: Pack, inner: [f64; 6], outer: [f64; 6], y_joint: f64, splits: [f64; 2],
  z_seam_passes: [bool; 2], column_reliefs: Tup<(i64, i64, String, [f64; 6])>, pump_bay: Option<[f64; 3]> }`.
  `_replace` is struct update: `Box { pack: Pack { placed: Val::dict(vec![]), ..box_.pack.clone() }, ..box_.clone() }`.
- `Pack`: the 30 fields (placed, front_ports, ... front_flank_reliefs), every one a `Val` holding
  exactly what Python holds, as one snapshot copies it (tuples are `Val::Tuple`, `placed` and
  `collet_plate` local dicts whose solids stay references, None is `Val::None`); a `PortField` or
  `Nameplate` in `port_field` / `nameplate` is the Python instance itself (`Val::Ref`). No pack
  callbacks after the one snapshot. View a field typed where you use it:
  `Tup::<[f64; 4]>::from_py(&pack.floor_bosses)?`, `py::at(&pack.collet_plate, "wall_aft_y")?.num()?`,
  `PortField::from_py(&pack.port_field)?` (when it is not None / `()`), and so on.
- `PortField { proud: Num, rim: Num, pockets: Val }`.
- `Bound { id: String, label: String, ok: bool, value: Val, target: Val, detail: Val }`; this module's
  bounds are `Bound::stated(id, label, ok, value: String, target: String, detail: Vec<String>)`
  (value/target as text, detail a list).
- `BoxReadings { bounds, lip, floor, under, pillars }`, each a `Val` (the snapshot's local dicts:
  `bounds` `{name: (lower, upper)}`, `lip` `{"front"|"back": {name: row}}`, `floor`/`under`/`pillars`
  keyed by tuples; look up with `readings.floor.get(Val::tuple(vec![..]))?`).
- `_ReadingBounds { xmin, xmax, ymin, ymax, zmin, zmax: f64 }` (Copy); `from_py` also reads any
  object with those attributes (a CadQuery `BoundBox` from `_boxes.boxed`); `to_py` makes a
  `_ReadingBounds`.

`record_bound` is a replaced name (machine-data and the recorders set it): call it through the
namespace, `py::call(&cx.ns.get("record_bound")?, vec![bound.to_py()?])?`, not `p1::record_bound`.

`State`: no field type changes; the constants are as the generated top level holds them (`f64`,
`i64`, `String`, arrays). Containers stay `Val` and are the namespace's own objects: `BOUNDS` (a list
of Python `Bound` instances), `_z_seam_passes` (dict), `_last_box` (`[None]`), `PIECE_PRINT_UP`,
`PIECE_COLORS`, `_ROOT_FACE` (local dicts), providers (`fits`, `_wago`, `_tray`, ...) and paths.
